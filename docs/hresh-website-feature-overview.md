# Hresh赫什个人网站功能总览

> 文档用途：对接外部宣传、访谈提纲、产品介绍、视频脚本和渠道发布时，统一网站功能与事实口径。
>
> 更新日期：2026-09-21
>
> 整理依据：当前仓库源码、产品数据、SEO 生成脚本、白板数据层、Supabase SQL/Edge Function、部署文档和现有宣传稿。

## 一、一句话定位

Hresh赫什个人网站是一个以“个人开发者工作台”为视觉语言的独立产品作品集：集中展示 Hresh赫什用 AI 做产品的经历、作品矩阵、公开构建方法，并提供一个带审核机制的访客互动白板。

对外可以概括为：

> 这里既是 Hresh赫什的作品总目录，也是一个可以逛、可以互动、可以继续追到产品入口的个人开发者工作台。

## 二、网站服务谁

- 想了解 Hresh赫什做过哪些产品、分别解决什么问题的人。
- 对 AI 开发、独立产品、效率工具和产品冷启动感兴趣的开发者与产品爱好者。
- 因通辽宇宙、LinkBox、TabNest、ReadCover 等单个产品进入，希望继续了解作者其他作品的人。
- 想在工作台留言、留下电子名片、贴纸或参与投票的普通访客。

## 五、主页功能

### 5.1 终端式启动体验

- 首次访问时，终端逐行输入 `whoami`、`cat about.md` 和个人定位，建立“Hresh赫什 = 用 AI 把想法做成产品的独立开发者”的第一印象。
- 访问者可通过 `Enter`、点击终端或“进入工作舱”跳过打字并启动。
- 回访用户会快速进入桌面，不重复完整启动动画。
- 启动过程包含进度反馈和屏幕缩放过渡，进入后切换到深空黑桌面。
- 系统开启“减少动态效果”时，会跳过强制缩放动画。

### 5.2 桌面式个人主页

桌面不是一张静态海报，而是一套可操作的个人信息空间：

- 桌面显示姓名、定位和“探索我的作品”入口。
- 右侧图标区承载个人介绍、作品索引、构建日志、设计 Skills 和外部身份入口。
- 右上品牌产品入口包括儿童 3D 自然博物馆、ReadCover、通辽宇宙等。
- 知乎、B站、掘金卡会先打开站内简介窗口，再提供跳转外部主页的按钮，避免访问者直接离开而失去上下文。
- 桌面实时显示时钟。
- 页面底部提供退场终端、再次启动和“回到开始”入口。

### 5.3 桌面窗口系统

点击桌面入口后会打开类似桌面操作系统的窗口：

- 支持打开、关闭、前置、拖动和调整尺寸。
- 同一入口重复点击时优先把已有窗口带到前台。
- 支持 `Escape` 关闭最上层窗口。
- 外部链接使用“链接档案窗口”说明它是什么，再允许访问者选择新标签页打开。

当前可打开的典型窗口包括：

- 关于 Hresh赫什
- 作品索引
- 通辽宇宙核心产品档案
- 通辽宇宙构建日志
- 设计 Skills
- 外部平台介绍卡

### 5.4 人物与柯基互动

- 人物和柯基可以在桌面范围内独立拖动。
- 点击“和我打个招呼”后，会触发招呼、柯基奔跑、来到人物身边和互动反馈。
- 互动完成后可“送它回去”，恢复到初始位置。
- 系统开启“减少动态效果”时不会强制播放角色动画。

### 5.5 星空背景互动

- 桌面背景使用缓慢闪烁的星点，不使用大面积霓虹或装饰光晕。
- 鼠标经过星点时，星点会被轻微推开。
- 点击空白桌面会产生短暂的星光反馈。
- 图标、窗口和人物交互区不会触发误点星光。

### 5.6 页尾与再次启动

- 页面滚动到底部后，桌面会收缩回 MacBook，并出现告别终端。
- 告别终端提供产品作品集和工作台入口。
- “回到开始”会重新播放启动流程，但滚动到底本身不会自动重启。

## 七、产品工作台功能

### 7.1 工作台定位

工作台不是匿名实时协作平台，也不是公开聊天室，而是“站长策展的访客互动墙”：

- 本地模式保留完整编辑与涂鸦能力。
- 线上模式公开读取审核通过的内容。
- 访客投稿先进入待审核区。
- 管理员审核通过后才进入公开白板。

### 7.2 工具栏

- `投稿` / `留言`：提交一段最多 140 字的访客留言。
- `贴一张`：打开模板选择器。
- `本地涂鸦`：进入画笔模式。
- `卡片`：移动端打开卡片导航抽屉。
- 缩放比例显示。
- 缩小、放大和“适应画布”。

### 7.3 画布操作

- 鼠标滚轮或触控板缩放，范围约为 20% 到 300%。
- 拖动画布空白区域进行平移。
- 卡片可以拖动；本地模式下只有创建者或管理员可移动。
- 双击可编辑卡片；拖动后不会误触投票。
- 左侧显示卡片列表，点击后定位到对应卡片。
- 移动端首次打开会优先把欢迎卡带入视野，避免先看到空白画布。

### 7.4 卡片类型

| 模板 | 用途 | 线上访客 | 本地访客 | 管理员 |
| --- | --- | --- | --- | --- |
| 留言卡 | 简短反馈与留言 | 可投稿 | 可创建 | 可创建 |
| 自我介绍卡 | 昵称、简介、标签、主页链接、颜色 | 可投稿 | 可创建 | 可创建 |
| 贴纸卡 | 白名单 Emoji 贴纸 | 可投稿 | 可创建 | 可创建 |
| 拍立得卡 | 图片与一句话说明 | 线上不支持 | 可创建 | 可创建 |
| 投票卡 | 单选、实时显示聚合票数和本人选择 | 仅可参与已有投票 | 可创建 | 可创建 |
| 胶带卡 | 标题与正文 | 不可创建 | 不可创建 | 可创建 |
| 个人卡 | 头像、名称、定位、信念、链接、二维码 | 不可创建 | 不可创建 | 可创建 |

| 叙事卡 | 长文本与署名 | 不可创建 | 不可创建 | 可创建 |

### 7.5 预制内容

代码内置品牌与产品种子卡，数据库故障时仍然可用：

- 欢迎说明
- Hresh赫什个人卡
- “你是怎么找到这里的？”投票
- LinkBox、ReadCover、通辽宇宙、儿童自然博物馆产品卡
- 构建方法与个人引用卡

### 7.6 本地涂鸦

- 支持画笔、橡皮擦、粗细、四种颜色和撤销。
- 橡皮擦只能擦除自己的笔迹。
- 涂鸦只保存在当前浏览器，线上模式不会上传。
- 涂鸦跟随画布缩放和平移。

### 7.7 线上审核与安全

线上模式采用“审核后发布”，不依赖第三方验证码：

- 公开客户端只能读取审核后的卡片和聚合票数。
- 投稿与投票统一经过 Supabase Edge Function。
- 服务端检查来源、字段、长度、蜜罐和填写时长。
- 使用 IP、设备和全站限流。
- 24 小时内检测同一来源的重复投稿。
- 待审核内容达到 100 条时自动停止接收新投稿。
- 图片、HTML 和任意模板数据不进入线上投稿。
- 访客图片和远端共享涂鸦不进入线上 MVP。

当前配额：

| 动作 | 配额 |
| --- | --- |
| 投稿 | 单 IP 2 次/10 分钟、5 次/天；单设备 2 次/10 分钟、3 次/天 |
| 全站投稿 | 20 次/小时、50 次/天 |
| 待审核队列 | 最多 100 条 |
| 投票 | 单 IP 30 次/小时；全站 1000 次/天 |
| 公开卡片读取 | 单次最多 200 张 |
| 刷新频率 | 每 60 秒刷新一次 |

管理员在 `wb_submissions` 中处理状态：

- `pending`：待审核。
- `published`：发布到公开白板。
- `rejected`：拒绝，不公开。
- `archived`：从公开白板撤回。

### 7.8 两种运行模式

| 模式 | 数据位置 | 能力 |
| --- | --- | --- |
| `local` | 当前浏览器 `localStorage` | 自由创建、编辑、拖动、投票和涂鸦；适合单浏览器演示 |
| `supabase` | Supabase 审核表与公开投影 | 公开读取、投稿审核、服务端投票和限流；适合正式线上 |

当前仓库的本地 `.env.local` 已配置为 `supabase` 模式。正式部署时仍需确认构建环境中的 Supabase 公开变量、Edge Function 和写入开关均已按生产要求配置。

## 八、SEO 与传播能力

### 8.1 首页 SEO

- 中文语言声明、viewport、theme color。
- canonical 和 `hreflang`。
- Open Graph 与 Twitter Card。
- `Person`、`WebSite`、`WebPage` 和产品 `ItemList` 结构化数据。
- 首页语义摘要中包含核心关键词和主要产品入口。
- 为键盘与屏幕阅读器保留清晰标题、导航和链接语义。

### 8.2 产品页 SEO

- 5 个独立产品页各有唯一标题、描述和 canonical。
- 使用 `WebApplication`、`MobileApplication` 或 `SoftwareApplication` 结构化数据。
- 使用 `BreadcrumbList` 建立站内层级。
- 每页包含 FAQ 和无 JavaScript 可读内容。
- 产品页互相提供“继续探索”关联链接。

### 8.3 搜索入口

- `robots.txt` 允许抓取并声明 sitemap。
- `sitemap.xml` 收录首页、产品视图、工作台和 5 个产品页。
- `whiteboard.html` 标记为 `noindex,follow`，避免与工作台主页面形成重复收录。

## 九、响应式与可访问性

- 桌面端、平板和手机端均有独立布局规则。
- 移动端使用底部主导航、卡片抽屉和触控友好的操作尺寸。
- 对 iPhone 安全区域使用 `safe-area-inset`。
- 支持 `prefers-reduced-motion`，减少装饰性动画。
- 窗口、弹窗和作品档案具备焦点管理、键盘关闭和焦点恢复。
- 图标按钮带有 `aria-label` 或可见文字说明。
- 主要图片提供替代文本。
- 关键操作保留可读文本和链接语义。

## 十、技术与部署概览


`npm run build` 会先重新生成产品页，再输出生产静态文件。部署只需要托管 `dist/`，主站和工作台都是静态入口，不需要 Node.js 常驻服务。

## 十一、适合宣传的核心卖点

### 11.1 三个最稳定的卖点

1. **不是单一产品页，而是一张会持续生长的个人产品地图。**
   网站把 Hresh赫什的 12 个作品、公开入口和构建方法集中到一个入口。

2. **把“独立开发者”做成了可以体验的桌面空间。**
   终端启动、窗口系统、作品档案、人物与柯基互动共同表达“一个人加 AI 也能完成从想法到上线”的工作方式。

3. **作品不是只列名称，而是讲清楚问题、能力和当前状态。**
   已上架、已公开、开源、未上线分别标注；同时给到网站、商店、源码或小程序入口。

### 11.2 推荐演示路线

适合 2 到 4 分钟的产品演示：

1. 从首页终端启动，进入桌面工作台。
2. 点击“作品索引”，说明 12 个作品档案和 10 个公开作品。

## 十二、对外宣传时需要避免的表述

不要宣传为：

- “12 个产品都已经上线或都可直接使用。”
- “匿名实时协作白板”或“人人可自由编辑的公共画布”。
- “访客可以上传图片、创建投票或永久共享涂鸦。”
- “支持秒级实时同步。”
- “网站有注册、账号、社区或独立审核后台。”
- “每个产品都有完整截图、价格、评分或用户评价。”
- “使用验证码保证投稿者一定是真人。”

准确表述应为：

- 12 个作品档案，其中 10 个为当前公开呈现作品。
- 线上白板是审核后发布的访客互动墙。
- 线上投稿支持留言、名片和贴纸，投票由站长预制。
- 公开内容每 60 秒刷新。
- 管理员通过 Supabase 表处理发布、拒绝和撤回。
- 未上线产品明确标注，不把完成等同于公开上线。

## 十三、维护这件文档时优先核对的事实

发布新宣传材料前，建议复查：

1. `src/components/homeData.js` 中的作品数量、状态和链接。
2. `src/seo/productPages.js` 是否新增或下线独立产品页。
3. `public/sitemap.xml` 是否与可公开页面一致。
4. `.env.local` 或生产构建环境是否仍使用预期的白板模式。
5. Supabase Edge Function 的写入开关、允许来源和限流配置是否生效。
6. 外部 App Store、Chrome Web Store、GitHub 和微信小程序是否仍可访问。

本次文档为代码级功能盘点，未登录 Apple、Google、微信等外部平台逐一验证商店或小程序的实际在线状态；正式宣传前应以目标渠道上的公开页面为准再做一次人工复测。
